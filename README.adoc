= EMES
:toc:

EMES (Executable Mechanical Engineering Specification) is an AI-native architecture for describing, generating, verifying, and iterating mechanical mechanisms as structured, version-controlled engineering data.

== Core idea

CAD is a derived artifact, not the source of truth.

[source,text]
----
requirements + design intent
          |
          v
 semantic mechanism IR
          |
    +-----+------+----------------+
    |            |                |
    v            v                v
  CAD         simulation       BOM / DFM
    \            |                /
     +-----------+---------------+
                 v
       deterministic evidence
                 |
                 v
        AI / optimizer patch
                 |
                 +------> repeat
----

The canonical source records requirements, topology, parameters, interfaces, load cases, objectives, constraints, and analysis intent. Generated CAD, simulation models, solver decks, reports, and BOMs remain reproducible projections.

A key architectural boundary is the separation between the semantic design graph and the evidence graph: AI may propose changes to the design, while registered tools and measurements produce the evidence used to accept or reject those changes.

Purchased components are also explicit engineering inputs. Motors, gearboxes, bearings, sensors, fasteners, battery cells, BMS units, power supplies, and converters can be normalized into versioned catalog snapshots containing dimensions, interfaces, unit-bearing properties, performance data, and attributed assets. A mechanism binds to a specific catalog/part digest rather than a live mutable vendor record.

== Current status

The architecture foundation and first external-tool vertical slice are merged:

[source,text]
----
EMES JSON
  -> semantic + catalog validation
  -> build123d -> exact BREP + STEP
  -> MJCF -> MuJoCo
  -> machine-readable evidence
----

The catalog layer supports deterministic import and pinned part binding. A synthetic motor fixture exercises the generic import contract, while `catalogs/maxon-496661.catalog.json` exercises the same architecture with an attributable real manufacturer motor snapshot. The maxon record is regenerated offline from a reviewed source snapshot and independently checked against hash-pinned manufacturer PDF/CAD assets.

The current power-system slice adds composable electrical components. A catalog-backed 21700-format cell can be combined by explicit series/parallel counts into a battery pack, constrained by a BMS, passed through a DC/DC converter, and evaluated against electrical load, energy, current, voltage, and mass constraints.

`catalogs/molicel-p45b.catalog.json` adds the first authoritative manufacturer battery-cell snapshot. It is normalized from the hash-pinned Molicel INR-21700-P45B Product Data Sheet v1.4 and preserves rating conditions such as the 80 degC cut-off on the 45 A continuous-discharge value rather than flattening them into unconditional limits. The existing executable pack example intentionally remains synthetic until thermal/SOC condition handling is executable.

A custom EMES language remains intentionally deferred until concrete examples prove it is necessary.
