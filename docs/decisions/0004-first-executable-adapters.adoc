= ADR 0004: First executable geometry and dynamics adapters
:status: accepted
:date: 2026-09-10

== Decision

The first external-tool EMES vertical slice uses:

* `build123d==0.11.1` for exact parametric solid generation, OpenCascade BREP export, and STEP interchange export.
* `mujoco==3.13.0` with generated MJCF for a headless rigid-body smoke test.

Both are pinned in `requirements-dev.txt`.

== Rationale

EMES should not implement a geometry kernel or a dynamics solver. build123d provides a local, open Python interface to Open Cascade geometry. MuJoCo provides a maintained, fast rigid-body engine and compact MJCF representation suitable for CI.

The purpose of these adapters is not to make either backend canonical. They prove that one semantic EMES source can be projected into real engineering tools and that resulting artifacts can be attributed to the same source digest.

== Determinism

Exact OpenCascade BREP is the geometry reproducibility artifact for this slice. MJCF is emitted using deterministic element ordering and numeric formatting. CI regenerates BREP and MJCF and compares their content digests together with catalog part digests, analytic metrics, constraint results, and the MuJoCo smoke result within the pinned toolchain.

STEP remains an interoperability artifact and uses a fixed header timestamp. However, observed CI execution showed that repeated STEPCAF exports of the same assembly can differ at the raw byte level. Therefore STEP SHA-256 is recorded as provenance for the emitted file but is not treated as the canonical geometry identity or as the determinism gate.

MuJoCo numerical results are only expected to be reproducible within the pinned toolchain. Cross-version bitwise identity is not an EMES requirement.

== Scope

This decision does not add FEA, controls, topology synthesis, or a custom EMES language. Those remain separate slices.
